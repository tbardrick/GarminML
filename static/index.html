What's Easy vs Hard
Easy to Implement ✓
📍

GPS Distance (Haversine)

Browser Geolocation API + basic spherical geometry. We get lat/lon/alt every second for free.

Easy
⏱️

Elapsed & Moving Time

Auto-pause: if speed < 0.3 m/s for > 15 s, stop the moving timer. Simple threshold logic.

Easy
⚡

Pace & Per-km Splits

distance ÷ time. Split at every 1,000 m boundary by linearly interpolating between GPS samples.

Easy
🗄️

Basic Storage & Sync

JSON file store (this app) or SQLite. REST API with five endpoints. Done in an afternoon.

Easy
Hard Parts Strava Spent Years On
📡

GPS Accuracy & Smoothing

Raw GPS jumps 5–30 m at start-up, overcounts distance by 3–8%. Kalman filter or Ramer–Douglas–Peucker needed. Accuracy field from the browser rarely < 5 m in urban canyons.

Hard
⛰️

Elevation Gain Accuracy

GPS altitude error is ±10–15 m. A 30-min flat run reports 40 m spurious gain. Strava discards GPS altitude and queries SRTM/Mapbox terrain DEMs server-side. Garmin watches add a barometric sensor + complementary filter.

Hard
🏆

Strava Segments

Matches every upload against millions of crowd-sourced polylines using Dynamic Time Warping + R-tree spatial index. Near-real-time at scale = pre-built PostGIS indexes and per-run fanout workers. Non-trivial distributed systems problem.

Hard
❤️

Heart Rate Zones

BLE/ANT+ sensor pairing, per-user max-HR calibration from history, time-in-zone histograms, HRV analysis. Each watch brand uses a different BLE profile.

Hard
👥

Social Feed & Kudos

Follow graph, activity fan-out on write vs pull-on-read trade-offs, notification delivery, spam/abuse detection, privacy controls per-activity. Basically building a social network.

Hard
🗺️

Route Matching ("You ran this before")

Approximate polyline similarity using Fréchet distance, stored in a trajectory index. Needs spatial indexing and fuzzy matching to handle slightly different GPS traces of the same route.

Hard
🔋

Battery vs Accuracy Trade-off

1 Hz GPS drains battery. Adaptive sampling (0.2 Hz when speed is steady) requires dead-reckoning interpolation between sparse points. Getting this wrong loses segments entirely.

Medium
📸

Photo Tagging & CDN

Correlate EXIF GPS+timestamp to route (timezone nightmares), generate multiple thumbnail sizes, privacy blur for faces/plates, CDN delivery, storage cost management.

Medium
This App's Tech Stack
Frontend: Pure HTML/CSS/JS (zero dependencies) — Browser Geolocation API, Canvas 2D route drawing, fetch() to REST API.

Backend: Python FastAPI + Pydantic v2 models + JSON file storage.

Analytics: Haversine formula, elevation noise filtering (2 m threshold), auto-pause detection, per-km split interpolation.

What's missing to become Strava: ~200 engineers and 15 years of iteration.
